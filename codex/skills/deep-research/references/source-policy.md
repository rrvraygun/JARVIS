# Source selection policy

## Route by claim

- Scientific efficacy or mechanism: original study and data, then systematic
  synthesis and consensus guidance.
- Current product/software behavior: official documentation, source, release
  artifacts, maintainer issue/announcement, then reproducible user reports.
- Security claim: vendor advisory, CVE authority, upstream patch, independent
  technical analysis, then field reports.
- User experience: diverse firsthand reports with environment and date; quantify
  only when sampling supports it.
- Recommendation: combine evidence with explicit user criteria and tradeoffs.

## Quality dimensions

Assess authority, proximity to the event, methodology, reproducibility,
independence, conflicts, recency, version match, completeness, and correction
history. A source can be authoritative yet irrelevant to the exact version.

## Confidence

- High: multiple independent high-quality sources directly support the claim.
- Moderate: good evidence with a material limitation or modest disagreement.
- Low: indirect, sparse, anecdotal, old, or conflicting evidence.
- Unknown: evidence cannot resolve the claim.
